# Local Spanish voice: non-billable live validation (2026-09-29)

Target: Windows Docker Desktop / WSL2, RTX 3060 12 GiB. No real OpenCode prompt, user recording, or hosted speech request was used. Synthetic speech only; the generated artifacts and temporary event DB are under `%LOCALAPPDATA%\Temp\opencode\spanish-voice-probe`.

## Exact procedure and observations

1. Prepended `$env:LOCALAPPDATA\Programs\DockerDesktop\resources\bin` to process PATH. `docker version` reported client 29.8.1, Docker Desktop server 29.8.1; initially `docker ps -a` had no containers. `./scripts/voice.ps1 start`, `docker compose -f deploy/compose.voice.yaml ps`, and `docker image inspect` showed the pinned `sha256:6ec12ebf890a17e0d4b242a8ba9e0eb1fb836e60e8a3c857aea9838d541579ac` running and publishing **only** `127.0.0.1:8000->8000/tcp`.
2. Immediate `./scripts/voice.ps1 models` failed with a startup connection reset; retry after server readiness verified both approved IDs in its live `/v1/registry`. Whisper Small installed into `deploy_voice-model-cache`; Kokoro installation returned HTTP 500 because the container could not resolve `us.aws.cdn.hf.co` to fetch `model.onnx`. The old `speaches-voice-probe-hf` cache (802 MiB) already contained the *same approved* Kokoro model. Mounted that volume **read-only** and copied missing Kokoro cache entries into `deploy_voice-model-cache` without overwriting the probe volume or existing cache entries (`cp -an /probe/models--speaches-ai--Kokoro-82M-v1.0-ONNX/. /deploy/models--speaches-ai--Kokoro-82M-v1.0-ONNX/`). The deploy cache grew from 464 MiB to approximately 802 MiB. Retried `./scripts/voice.ps1 models`: both IDs listed installed. This is cache-assisted installation, **not** evidence that a fresh first-run Kokoro download works on this network.
3. `npm run build`; called `dist/voice-client.js` against loopback for Spanish Kokoro `ef_dora` TTS (77-character synthetic sentence): 207,916-byte WAV, **4,017 ms cold request** including model load (server log 2.59 s model load + 1.381 s generation). `ffprobe` on the generated WAV showed PCM signed 16-bit mono, 24 kHz, 4.331 s. This is a locally decodable/playable WAV; acoustic listening by a human was not performed. Seeded a synthetic `waiting-for-input` event and invoked the **real** `node dist/cli.js speak --config <temp-config> --event-id synthetic-event --output <temp>/event-status.wav`; returned success, and `ffprobe` reported PCM signed 16-bit mono, 24 kHz, 4.181 s. No OpenCode session was contacted by `speak`.
4. Used **container ffmpeg** to encode the synthetic Spanish WAV to AAC M4A (55,075 bytes). Called `VoiceClient.transcribe` against loopback with both inputs. WAV: **2,174 ms cold**, text `Hola, este es un mensaje de prueba en español, estoy esperando una respuesta.`; AAC M4A: **326 ms warm**, same text. Input was generated speech, not an independent human recording. This validates these particular containers/codecs, not all WAV/M4A codecs.
5. `docker exec deploy-speaches-1 nvidia-smi --query-gpu=memory.used,memory.total,utilization.gpu --format=csv,noheader`: **861 MiB / 12,288 MiB / 0%** before inference; **986 MiB** after TTS; **1,702 MiB / 12,288 MiB / 17%** immediately after WAV/M4A transcription; **1,700 MiB / 12,288 MiB / 0%** later. Server logs show Whisper model load and 4.331 s / 4.352 s transcription processing, plus Kokoro model load and generation. This is actual observed GPU memory and utilization change during the inference window, stronger than CUDA availability alone; sampling was not process-attributed or simultaneous with the inference kernel. **Do not claim every TTS operation executed on CUDA**: Kokoro ONNX execution provider was not verified directly.
6. `./scripts/voice.ps1 stop`, `docker compose -f deploy/compose.voice.yaml ps` (empty), and `docker volume ls --filter name=voice-model-cache` (persistent `deploy_voice-model-cache`). The existing `speaches-voice-probe-hf` volume was preserved. No container was left running.

## Remaining acceptance gaps

- A clean-room first-run model download is network-blocked by the CDN DNS failure; cache-assisted deployment works. The startup-to-models race also requires waiting for readiness before `models`.
- No human listening test or independently recorded Spanish audio. WAV decode/format and synthetic Spanish STT/TTS were checked locally.
- No process-attributed GPU profiling or proof of Kokoro ONNX CUDA inference. Measurements above must not be interpreted as that proof.
- Real lifecycle-event persistence and a live confirmed reply to OpenCode are still unverified. A confirmed prompt may be billable and requires separate approval; **no live OpenCode prompt was issued**. Default discovery/auth-header wiring is unit-tested with mocks, not with a live session.
- Partial output cleanup in `speak` uses a non-atomic path stat/inode comparison followed by unlink; a simultaneous path replacement in that interval is a residual race. Do not promise absolute replacement safety.
